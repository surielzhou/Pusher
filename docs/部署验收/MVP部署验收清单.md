# MVP 部署验收清单

## 文档目的

本文提供 MVP 上线前可逐项执行的部署与验收清单，配套 `docs/部署验收/MVP部署验收方案与需求动线Review.md` 使用。

## 基础信息

验收执行前填写：

```text
验收日期：
验收版本或提交：
部署环境：
应用访问地址：
验收人：
```

## 1. 环境变量清单

| 配置项 | 必填 | 示例 | 验收要求 |
| --- | --- | --- | --- |
| `PORT` | 否 | `3000` | 应用启动端口；未设置时默认 `3000`。 |
| `DATABASE_URL` | 正式持久化部署必填 | `file:./data/pusher.db` 或 PostgreSQL URL | 使用 SQLite/PostgreSQL 时必须配置；当前内存仓储验收环境需明确接受数据重启丢失。 |
| `AI_TEXT_PROVIDER` | 真实生成必填 | `fake` / `openai` / `custom` | MVP 验收可使用可控 fake adapter；真实生成环境需指定 provider。 |
| `AI_TEXT_API_KEY` | 真实生成必填 | `<secret>` | 只在真实文本生成 adapter 需要外部 API 时配置，不写入代码仓库。 |
| `FILE_STORAGE_ROOT` | 启用上传图片时必填 | `/var/lib/pusher/uploads` | 上传图片或导出文件需要稳定存储目录；仅使用配图建议时可为空。 |
| `APP_BASE_URL` | 正式部署必填 | `https://pusher.example.com` | 用于验收记录和后续链接生成；本地验收可使用 `http://127.0.0.1:3000`。 |
| `LOG_LEVEL` | 否 | `info` | 建议正式部署设置为 `info`，排障时临时切换为 `debug`。 |

验收勾选：

- [ ] 已确认所有必填环境变量均已配置。
- [ ] 密钥未提交到仓库、文档或验收记录。
- [ ] fake adapter 与真实 adapter 的使用场景已记录。
- [ ] 如使用内存仓储，已记录数据不可持久化的验收限制。

## 2. 数据库初始化步骤

当前代码基线使用内存仓储，不需要执行迁移命令；正式持久化部署启用 SQLite、PostgreSQL 或 Prisma 后，按以下步骤验收。

1. 确认 `DATABASE_URL` 指向目标数据库。
2. 执行迁移命令：

```bash
npx prisma migrate deploy
```

3. 如未使用 Prisma，执行项目实际数据库迁移或初始化脚本。
4. 验证数据表或等价结构已包含文章、图片、review、发布记录和状态事件。
5. 写入一条测试文章记录，确认应用服务能读取。

验收勾选：

- [ ] 已确认数据库连接可用。
- [ ] 已执行迁移或确认当前内存仓储无需迁移。
- [ ] 文章、图片、review、发布记录、状态事件结构可用。
- [ ] 初始化失败时的回滚或恢复方式已确认。

## 3. 构建命令

安装依赖：

```bash
npm install
```

运行构建：

```bash
npm run build
```

通过标准：

- `npm install` 无阻塞错误。
- `npm run build` 退出码为 0。
- 没有 TypeScript 编译错误或阻塞发布的构建错误。

验收勾选：

- [ ] 依赖安装完成。
- [ ] 构建命令执行成功。
- [ ] 构建日志已归档或记录关键输出。

## 4. 启动命令

启动应用：

```bash
npm start
```

本地验收访问：

```text
http://127.0.0.1:3000
```

如需指定端口：

```bash
PORT=3001 npm start
```

通过标准：

- 应用进程启动成功。
- 工作台页面可访问。
- 启动日志没有数据库连接、配置缺失或端口占用导致的失败。

验收勾选：

- [ ] 应用进程已启动。
- [ ] 工作台页面可访问。
- [ ] 启动日志无阻塞错误。
- [ ] 应用访问地址已写入基础信息。

## 5. 上线前验收步骤

### 自动化测试

执行：

```bash
npm test
npm run test:e2e
```

通过标准：

- 单元测试通过。
- E2E 测试通过。
- 若 E2E 依赖外部服务，已切换到稳定测试配置或 mock。

验收勾选：

- [ ] 单元测试通过。
- [ ] E2E 测试通过。
- [ ] 失败用例已修复或明确列为阻塞问题。

### 主用户动线

- [ ] 进入工作台。
- [ ] 新建文章。
- [ ] 选择科技互联网、金融、文学任一方向并输入主题。
- [ ] 生成图文草稿。
- [ ] 编辑标题、摘要、正文和配图建议。
- [ ] 提交 review。
- [ ] Review 通过。
- [ ] 进入发布准备。
- [ ] 生成公众号可复制内容。

通过标准：

- 状态经过 `drafting`、`editing`、`pending_review`、`approved`、`pending_publish`。
- 发布准备内容包含标题、摘要、正文和图片清单或配图说明。

### Review 门禁

- [ ] 未提交 review 的文章不能进入发布准备。
- [ ] Review 退回后记录退回原因。
- [ ] 暂不发布文章不能进入发布准备。
- [ ] Review 通过后修改正文或图片，需要重新 review。

### 内容方向

- [ ] 科技互联网内容包含行业背景、技术或产品变化、趋势判断。
- [ ] 金融内容不承诺收益、不提供直接投资建议，并展示风险提示或 review 检查提醒。
- [ ] 文学内容具备主题表达、可读性和文学表达。
- [ ] 配图建议与正文主题相关。

### 发布准备

- [ ] 可复制内容包含标题。
- [ ] 可复制内容包含摘要。
- [ ] 可复制内容包含正文。
- [ ] 可复制内容包含图片清单、图片占位或配图说明。
- [ ] 标记已发布后状态进入 `published`。
- [ ] 标记发布失败时必须填写失败原因，状态进入 `publish_failed`。

## 6. 回滚方案

### 回滚触发条件

- 应用无法启动。
- 数据库迁移失败且无法快速修复。
- 主用户动线无法完成。
- 未通过 review、暂不发布或修改后未重新 review 的文章可以进入发布准备。
- 发布准备内容缺少正文、图片清单或配图说明。

### 回滚步骤

1. 停止当前版本应用。
2. 恢复上一稳定版本应用包或镜像。
3. 如有数据库迁移，执行迁移工具回滚；无法回滚时恢复部署前备份。
4. 重新启动上一稳定版本。
5. 执行工作台访问、历史文章访问和主流程冒烟检查。
6. 记录回滚原因、影响范围和后续修复负责人。

回滚验收勾选：

- [ ] 上一稳定版本可用。
- [ ] 数据库备份或迁移回滚路径已确认。
- [ ] 回滚后工作台可访问。
- [ ] 回滚后主流程冒烟通过。
- [ ] 回滚记录已归档。

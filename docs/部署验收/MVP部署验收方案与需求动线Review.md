# MVP 部署验收方案与需求动线 Review

## 文档目的

本文定义 MVP 上线前的部署准备、环境检查、验收流程、验收清单和需求/用户动线覆盖 Review。

输入文档：

- `docs/需求/初版需求故事.md`
- `docs/设计/用户动线拆分.md`
- `docs/设计/详细设计.md`
- `docs/测试/MVP测试方案与需求动线Review.md`
- `docs/开发计划/Phase开发计划-多AI并行.md`

## 验收目标

- 确认 MVP 能支撑公众号图文内容生成和发布准备闭环。
- 确认科技互联网、金融、文学三类方向可用。
- 确认文章发布前必须经过人工 review。
- 确认未通过 review、暂不发布、内容修改后未重新 review 的文章不能进入发布准备。
- 确认发布准备能输出公众号可复制内容。
- 确认测试、部署、回滚和基础运行检查有明确执行路径。

## 部署前置条件

### 代码与分支

- Phase 0 到 Phase 6 已完成并合并。
- 共享领域契约已冻结并通过 review。
- 未合并的增强能力不进入 MVP 部署包。
- 工作区没有未说明的临时改动。

### 测试条件

- 单元测试通过。
- 集成测试通过。
- E2E 主流程通过。
- 发布门禁测试通过。
- 手工验收用例已执行或安排执行。

### 配置条件

MVP 需要确认以下配置：

| 配置项 | 说明 | MVP 要求 |
| --- | --- | --- |
| 数据库连接 | SQLite 或 PostgreSQL 连接 | 必填 |
| AI 文本生成配置 | 文本生成 adapter 所需配置 | 必填或使用可控 fake adapter |
| 文件存储路径 | 上传图片或导出内容存储位置 | 如启用上传则必填 |
| 应用访问地址 | 用户访问系统的 URL | 必填 |
| 日志级别 | 运行日志配置 | 建议开启 info 和 error |

## 部署步骤

### 1. 安装依赖

命令：

```bash
npm install
```

通过标准：

- 依赖安装完成。
- 没有阻塞安装的错误。

### 2. 初始化数据库

命令按最终技术栈确定。若使用 Prisma，建议为：

```bash
npx prisma migrate deploy
```

通过标准：

- 数据表包含文章、图片、review、发布记录、状态事件或等价结构。
- 迁移执行成功。

### 3. 构建应用

命令：

```bash
npm run build
```

通过标准：

- 构建成功。
- 没有 TypeScript 编译错误。
- 没有阻塞发布的构建错误。

### 4. 启动应用

命令：

```bash
npm start
```

通过标准：

- 应用启动成功。
- 工作台页面可访问。
- 日志无启动失败错误。

### 5. 执行上线前测试

命令建议：

```bash
npm test
npm run test:e2e
```

通过标准：

- 单元测试通过。
- E2E 测试通过。
- 如 E2E 依赖外部服务，应使用稳定测试配置或 mock。

## 验收流程

### 验收角色

| 角色 | 职责 |
| --- | --- |
| 产品验收人 | 确认需求和用户动线是否满足 |
| 技术验收人 | 确认部署、测试和状态规则是否满足 |
| 内容 Review 人 | 确认图文内容质量和发布前 review 体验 |
| 发布执行人 | 确认可复制内容能用于公众号发布准备 |

初版可以由同一人承担多个角色，但验收记录需要覆盖上述职责。

### 验收顺序

1. 环境可用性验收。
2. 主用户动线验收。
3. 三类内容方向验收。
4. Review 门禁验收。
5. 发布准备验收。
6. 分支和异常验收。
7. 文档与回滚验收。

## 主用户动线验收

### AC-FLOW-001：完整发布准备闭环

步骤：

1. 进入工作台。
2. 新建文章。
3. 选择科技互联网方向。
4. 输入主题。
5. 生成图文草稿。
6. 编辑标题、摘要、正文和配图建议。
7. 提交 review。
8. Review 通过。
9. 进入发布准备。
10. 生成公众号可复制内容。

通过标准：

- 文章状态依次经过 `drafting`、`editing`、`pending_review`、`approved`、`pending_publish`。
- 生成内容包含标题、摘要、正文和配图建议。
- 发布准备内容包含标题、摘要、正文和图片清单。

### AC-FLOW-002：历史文章可追踪

步骤：

1. 进入历史文章页。
2. 按内容方向筛选。
3. 按状态筛选。
4. 打开已创建文章。

通过标准：

- 能看到文章标题、内容方向、状态、更新时间。
- 能从列表进入编辑、review 或发布准备的对应页面。

## 内容方向验收

### AC-CATEGORY-001：科技互联网方向

步骤：

1. 选择科技互联网方向。
2. 输入一个科技互联网主题并生成草稿。

通过标准：

- 内容体现行业背景、技术或产品变化、趋势判断。
- 生成配图建议与科技互联网主题相关。

### AC-CATEGORY-002：金融方向

步骤：

1. 选择金融方向。
2. 输入一个金融主题并生成草稿。
3. 进入 Review 页检查风险提示。

通过标准：

- 内容避免承诺收益。
- 内容避免直接投资建议。
- 展示风险提示或 review 检查提醒。
- 配图建议与金融分析或市场观察相关。

### AC-CATEGORY-003：文学方向

步骤：

1. 选择文学方向。
2. 输入文学主题并生成草稿。

通过标准：

- 内容有明确主题表达。
- 文章具备可读性和文学表达。
- 配图建议与阅读、作品、作者、意象或文本主题相关。

## Review 门禁验收

### AC-REVIEW-001：未提交 review 不可发布

步骤：

1. 生成文章草稿。
2. 不提交 review。
3. 尝试进入发布准备。

通过标准：

- 系统阻断发布准备。
- 提示文章需要先提交 review 或等待 review 通过。

### AC-REVIEW-002：Review 退回修改

步骤：

1. 提交 review。
2. 在 Review 页选择退回修改。
3. 填写退回原因。
4. 返回图文编辑页修改内容。
5. 再次提交 review。

通过标准：

- 退回原因被记录。
- 文章状态进入 `review_rejected`。
- 修改后可重新进入 `pending_review`。

### AC-REVIEW-003：暂不发布

步骤：

1. 提交 review。
2. 选择暂不发布。
3. 尝试进入发布准备。

通过标准：

- 文章状态进入 `not_publish`。
- 发布准备被阻断。

### AC-REVIEW-004：通过后修改需重新 review

步骤：

1. Review 通过文章。
2. 修改正文或图片。
3. 尝试进入发布准备。

通过标准：

- 文章回到 `editing` 或提示内容版本不匹配。
- 发布准备被阻断。
- 需要重新提交 review。

## 发布准备验收

### AC-PUBLISH-001：生成公众号可复制内容

步骤：

1. 对 review 通过文章进入发布准备页。
2. 生成发布内容。
3. 查看导出内容。

通过标准：

- 导出内容包含公众号标题。
- 导出内容包含摘要。
- 导出内容包含正文。
- 导出内容包含图片清单、图片占位或配图说明。

### AC-PUBLISH-002：标记发布结果

步骤：

1. 在发布准备页标记已发布。
2. 对另一篇文章标记发布失败并填写原因。

通过标准：

- 已发布文章状态进入 `published`。
- 发布失败文章状态进入 `publish_failed`。
- 发布失败原因被记录。

## 分支与异常验收

| 验收 ID | 场景 | 通过标准 |
| --- | --- | --- |
| AC-ERR-001 | 生成失败 | 状态进入 `generation_failed`，保留生成配置，可重试 |
| AC-ERR-002 | 缺少标题提交 review | 阻断提交，提示缺少标题 |
| AC-ERR-003 | 缺少正文提交 review | 阻断提交，提示缺少正文 |
| AC-ERR-004 | 缺少图片或配图建议提交 review | 阻断提交，提示需要图片内容或配图方案 |
| AC-ERR-005 | 发布失败 | 状态进入 `publish_failed`，记录失败原因 |
| AC-ERR-006 | 非法状态流转 | 操作被阻断，记录异常事件 |

## 回滚方案

触发回滚的情况：

- 应用无法启动。
- 数据库迁移失败且无法快速修复。
- 主用户动线无法完成。
- 未通过 review 的文章可以进入发布准备。
- 发布准备内容缺少正文或图片清单。

回滚步骤：

1. 停止当前版本应用。
2. 恢复上一稳定版本应用包。
3. 如有数据库迁移，按迁移工具回滚或恢复部署前备份。
4. 重新启动上一稳定版本。
5. 执行工作台访问、文章列表访问和主流程冒烟检查。

## 通过标准

MVP 可以通过验收的最低标准：

- 主用户动线可完整走通。
- 三类内容方向均可生成文章草稿。
- 文章有标题、摘要、正文和图片内容或配图方案。
- 发布前 review 门禁有效。
- 未通过 review、暂不发布、修改后未重新 review 的文章不能进入发布准备。
- 发布准备可生成公众号可复制内容。
- 测试方案和部署验收方案均已归档。

# 功能模块划分与需求动线 Review

## 文档目的

本文基于以下文档进行功能模块划分，并回看模块是否覆盖初版需求和用户动线：

- `docs/需求/初版需求故事.md`
- `docs/设计/用户动线拆分.md`
- `docs/设计/概要设计.md`

本次划分服务 MVP，不直接引入多人权限、公众号接口直发、完整素材库和复杂历史版本对比。

## 模块划分原则

- 以用户动线为主线：模块必须能串起新建、生成、编辑、review、发布准备的完整闭环。
- 以文章状态为约束：模块操作必须受文章状态控制，未通过 review 不能进入发布。
- 以扩展点保留边界：图片来源、公众号发布、金融合规和多人 review 暂不写死。
- 以 MVP 为优先级：先完成单人可用闭环，再扩展协作和自动化能力。

## 功能模块总览

```text
内容工作台模块
  -> 文章创建与生成配置模块
  -> 图文内容生成模块
  -> 图片与配图模块
  -> 图文编辑模块
  -> Review 审核模块
  -> 发布准备模块
  -> 历史文章与状态筛选模块

支撑模块
  -> 文章状态流转模块
  -> 内容完整性校验模块
  -> 生成策略与提示词模块
  -> 数据存储模块
  -> 日志与异常模块
  -> 外部能力适配模块
```

## 用户可感知功能模块

### 1. 内容工作台模块

定位：

- 作为用户进入系统后的起点。
- 聚合当前需要处理的文章任务。

核心能力：

- 新建文章入口。
- 展示最近草稿。
- 展示待编辑、待 review、待发布文章。
- 按内容方向和状态快速筛选。

关联用户动线：

- 进入创作入口。
- 历史文章查看。
- 从待处理列表继续编辑、review 或发布准备。

关联需求：

- 支持文章生成和推送链路入口。
- 支持文章状态维护和历史文章查看。

MVP 优先级：高。

### 2. 文章创建与生成配置模块

定位：

- 负责收集生成文章所需输入。

核心能力：

- 创建文章任务。
- 选择内容方向：科技互联网、金融、文学。
- 输入主题或关键词。
- 输入目标读者、文章风格、篇幅要求、参考素材。
- 保存生成配置。

关联用户动线：

- 选择内容方向。
- 输入主题并确认生成。

关联需求：

- 支持按主题或方向生成公众号文章。
- 内容方向至少覆盖科技互联网、金融、文学三类。

MVP 优先级：高。

### 3. 图文内容生成模块

定位：

- 负责把用户输入转化为公众号文章草稿。

核心能力：

- 根据内容方向选择生成策略。
- 生成标题。
- 生成摘要。
- 生成正文结构。
- 生成正文内容。
- 生成配图建议。
- 对金融内容生成风险提示建议。
- 处理生成失败和重试。

关联用户动线：

- 生成图文文章草稿。
- 生成结果不满意后重新生成全文或局部内容。

关联需求：

- 系统能产出结构完整的公众号文章草稿。
- 文章格式需要有文有图。
- 支持生成适合公众号阅读场景的标题、摘要、正文结构和配图建议。

MVP 优先级：高。

### 4. 图片与配图模块

定位：

- 负责文章图片内容、配图方案和图片来源管理。

核心能力：

- 保存配图建议。
- 记录图片描述、来源、插入位置。
- 支持人工上传图片的扩展。
- 支持 AI 图片生成的扩展。
- 支持素材库选择的扩展。
- 标记图片缺失或待补充。

关联用户动线：

- 编辑和补充图文内容。
- 图片不合适时替换、上传、重新生成或保留配图建议。

关联需求：

- 每篇文章必须包含文字内容和至少一项图片内容或配图方案。
- review 人需要检查图文匹配度。

MVP 优先级：高。

初版建议：

- 先支持“配图方案”和“人工维护图片记录”。
- 图片真实生成、素材库和外部搜索作为后续外部能力适配。

### 5. 图文编辑模块

定位：

- 负责 AI 草稿进入人工编辑阶段。

核心能力：

- 编辑标题。
- 编辑摘要。
- 编辑正文。
- 调整图片和正文段落的对应关系。
- 查看公众号阅读预览。
- 保存编辑结果。
- 提交 review。

关联用户动线：

- 编辑和补充图文内容。
- Review 退回后修改文章并再次提交。

关联需求：

- review 前允许人工介入修改标题、摘要、正文和图片。
- AI 生成内容作为草稿，最终由用户确认。

MVP 优先级：高。

### 6. Review 审核模块

定位：

- 负责发布前人工 review，是发布控制的关键模块。

核心能力：

- 展示完整图文预览。
- 展示内容方向、生成配置和风险提示。
- 填写审核意见。
- 标记通过。
- 标记退回修改。
- 标记暂不发布。
- 保存审核记录。

关联用户动线：

- 提交 Review。
- Review 图文文章。
- Review 退回修改。
- 暂不发布。

关联需求：

- 文章发布前必须经过人工 review。
- review 人可以查看完整图文内容。
- review 人可以确认、修改、退回或批准。
- 未通过 review 的文章不得进入正式发布或推送环节。

MVP 优先级：高。

### 7. 发布准备模块

定位：

- 负责把审核通过的文章整理成可发布形态。

核心能力：

- 只接受 `已通过` 或 `待发布` 状态的文章。
- 展示最终发布预览。
- 输出可复制到公众号后台的标题、摘要、正文和图片清单。
- 标记发布准备状态。
- 标记人工发布结果。
- 记录发布失败原因。
- 保留公众号接口对接扩展点。

关联用户动线：

- Review 通过后进入发布准备。
- 发布失败后修正并重试。

关联需求：

- 审核通过后的文章进入推送或发布准备流程。
- 初版允许先生成公众号可复制内容。

MVP 优先级：高。

### 8. 历史文章与状态筛选模块

定位：

- 负责文章记录查询和状态管理入口。

核心能力：

- 展示文章列表。
- 按内容方向筛选。
- 按文章状态筛选。
- 按创建时间筛选。
- 查看文章详情。
- 查看 review 和发布记录摘要。

关联用户动线：

- 历史文章页。
- 从历史记录回到编辑、review 或发布准备。

关联需求：

- 文章状态需要可追踪。
- review 结果需要影响文章后续状态。

MVP 优先级：中。

## 支撑功能模块

### 9. 文章状态流转模块

定位：

- 统一控制文章状态变化，避免状态规则分散到各页面。

核心能力：

- 定义文章状态枚举。
- 校验状态流转是否合法。
- 阻止未审核文章进入发布准备。
- 阻止暂不发布文章进入发布。
- 记录关键状态变化时间。

支撑的状态流：

```text
草稿中 -> 待编辑 -> 待Review -> 已通过 -> 待发布 -> 已发布
草稿中 -> 生成失败 -> 草稿中
待Review -> Review退回 -> 待编辑 -> 待Review
待Review -> 暂不发布
待发布 -> 发布失败 -> 待发布
```

MVP 优先级：高。

### 10. 内容完整性校验模块

定位：

- 在提交 review 前校验文章是否满足最低条件。

核心能力：

- 校验标题是否存在。
- 校验正文是否存在。
- 校验内容方向是否存在。
- 校验至少有一项图片内容或配图方案。
- 返回明确缺失项。

关联需求：

- 每篇文章必须有文有图。
- 文章必须经过 review 才能发布。

MVP 优先级：高。

### 11. 生成策略与提示词模块

定位：

- 管理不同内容方向的生成策略，避免所有内容使用同一套生成逻辑。

核心能力：

- 科技互联网方向生成策略。
- 金融方向生成策略。
- 文学方向生成策略。
- 公众号文章结构模板。
- 配图建议模板。
- 金融风险提示模板。

关联需求：

- 项目主要面向科技互联网、金融、文学。
- 文章需要适合公众号阅读场景。
- 金融类内容需要保留风险提示扩展点。

MVP 优先级：高。

### 12. 数据存储模块

定位：

- 保存文章、图片、review、发布记录和状态数据。

核心对象：

- `Article`
- `ArticleImage`
- `ReviewRecord`
- `PublishRecord`

MVP 优先级：高。

### 13. 日志与异常模块

定位：

- 支撑生成失败、发布失败和状态异常排查。

核心能力：

- 记录生成失败原因。
- 记录发布失败原因。
- 记录非法状态流转拦截。
- 记录外部能力调用失败。

MVP 优先级：中。

### 14. 外部能力适配模块

定位：

- 隔离 AI 模型、图片能力和公众号接口，避免业务流程直接依赖具体供应方。

核心能力：

- AI 文本生成适配。
- AI 图片生成适配。
- 人工上传或素材库适配。
- 公众号草稿箱或发布接口适配。

MVP 优先级：中。

初版建议：

- 只需要定义适配边界。
- 公众号接口和复杂图片能力可以后续实现。

## 分支动线覆盖 Review

### 生成结果不满意

覆盖模块：

- 图文内容生成模块。
- 生成策略与提示词模块。
- 图文编辑模块。

Review 结论：

- 已覆盖重新生成全文和局部内容的扩展边界。
- MVP 可以先支持重新生成全文，局部重生成作为增强项。

### 图片不合适

覆盖模块：

- 图片与配图模块。
- 图文编辑模块。
- 外部能力适配模块。

Review 结论：

- 已覆盖替换、上传、重新生成和保留配图建议的边界。
- MVP 建议先支持配图方案记录，真实图片生成和素材库后续扩展。

### Review 退回修改

覆盖模块：

- Review 审核模块。
- 文章状态流转模块。
- 图文编辑模块。

Review 结论：

- 已覆盖退回原因记录、回到编辑、再次提交 review。

### 暂不发布

覆盖模块：

- Review 审核模块。
- 文章状态流转模块。

Review 结论：

- 已覆盖暂不发布状态。
- 发布准备模块已明确只接受 `已通过` 或 `待发布` 状态文章，防止暂不发布文章进入发布链路。

### 发布失败

覆盖模块：

- 发布准备模块。
- 日志与异常模块。
- 文章状态流转模块。

Review 结论：

- 已覆盖失败原因记录和重新进入待发布。
- 如果初版只做人工复制发布，发布失败可先由用户手动标记。

## 模块边界 Review

### 需要保持独立的边界

- 图文内容生成模块不直接修改 review 状态。
- Review 审核模块不直接生成文章内容，只做审核决策和意见记录。
- 发布准备模块只处理已通过文章，不绕过状态流转模块。
- 图片与配图模块只管理图片和配图方案，不决定文章是否可发布。
- 外部能力适配模块不承载业务规则，只封装外部调用。

### 容易混淆的边界

- Review 页是否允许直接编辑文章：初版建议不在 Review 页直接编辑，退回后到图文编辑页修改，避免审核动作和编辑动作混在一起。
- 图片初版到底是“真实图片”还是“配图建议”：需求允许“图片内容或配图方案”，因此 MVP 可以先按配图建议闭环。
- 发布准备是否等于正式发布：初版建议区分。发布准备先生成公众号可复制内容，正式公众号接口对接后续扩展。
- 金融合规是否自动拦截：初版先做风险提示和人工 review 检查，自动合规拦截后续扩展。

## Review 结论

模块划分可以覆盖当前初版需求和用户动线。当前最小闭环为：

```text
新建文章
  -> 选择方向和主题
  -> 生成图文草稿
  -> 人工编辑
  -> 提交 review
  -> review 决策
  -> 发布准备
```

后续进入开发计划时，建议按以下优先级拆阶段：

1. 文章状态、数据对象和内容完整性校验。
2. 文章创建、生成配置和图文草稿生成。
3. 图文编辑、图片与配图管理。
4. Review 审核和状态流转拦截。
5. 发布准备、历史文章和状态筛选。
6. AI 图片、素材库、公众号接口和金融合规增强。

# 概要设计

## 设计目标

本项目面向公众号图文内容生产，初版围绕科技互联网、金融、文学三个方向，建立从选题、图文生成、人工编辑、发布前 review 到发布准备的最小闭环。

概要设计优先解决三个问题：

- 内容生成链路清晰：用户输入主题后，系统能生成结构完整的公众号图文草稿。
- 人工介入点明确：文章发布前必须经过 review，review 结果控制后续状态。
- 后续扩展留边界：图片来源、公众号发布接口、多人审核和版本管理不在初版强耦合。

## 设计原则

- 状态驱动：文章的可操作能力由文章状态决定，避免未审核内容进入发布环节。
- 模块解耦：生成、编辑、review、发布准备分别由独立模块承担。
- 人工优先：AI 生成内容默认是草稿，最终发布权保留给用户。
- MVP 收敛：初版先支持单人使用和发布准备，不强依赖公众号接口直发。
- 内容安全可扩展：金融类内容保留风险提示和合规检查扩展点。

## 系统边界

### 初版包含

- 文章创建与生成配置。
- 科技互联网、金融、文学三类内容方向。
- 图文文章草稿生成。
- 标题、摘要、正文、图片内容或配图方案编辑。
- 发布前 review。
- review 通过、退回修改、暂不发布。
- 审核通过后的发布准备。
- 文章状态维护和历史文章查看。

### 初版不强制包含

- 多人账号、角色权限和协同审核。
- 公众号接口直接发布。
- 完整素材库。
- 复杂排版编辑器。
- 多版本差异对比。
- 自动化内容合规审核闭环。

## 总体架构

```text
用户界面层
  -> 创作入口
  -> 生成配置页
  -> 图文编辑页
  -> Review 页
  -> 发布准备页
  -> 历史文章页

业务服务层
  -> 文章服务
  -> 内容生成服务
  -> 图片服务
  -> Review 服务
  -> 发布准备服务
  -> 状态流转服务

基础能力层
  -> 数据存储
  -> AI 文本生成能力
  -> AI 图片生成或配图建议能力
  -> 文件或图片存储
  -> 日志与异常记录
```

## 核心模块

### 文章服务

负责文章生命周期管理，是系统的主业务入口。

主要职责：

- 创建文章任务。
- 保存文章标题、摘要、正文、内容方向和生成配置。
- 查询文章详情和文章列表。
- 维护文章与图片、review、发布记录之间的关联。

### 内容生成服务

负责根据用户输入生成公众号文章草稿。

主要职责：

- 根据内容方向选择生成策略。
- 生成标题、摘要、正文结构和正文内容。
- 输出配图需求描述。
- 为金融类内容生成风险提示建议。
- 在生成失败时返回可重试的错误信息。

### 图片服务

负责管理文章图片内容或配图方案。

主要职责：

- 接收内容生成服务输出的配图建议。
- 支持后续接入 AI 图片生成、人工上传或素材库选择。
- 记录图片来源、图片说明和图片与正文段落的关系。

初版可以先将图片定义为“图片内容或配图方案”，避免过早绑定具体图片来源。

### Review 服务

负责发布前人工审核。

主要职责：

- 接收文章提交 review。
- 校验文章是否满足最低 review 条件。
- 记录 review 结果和审核意见。
- 控制文章进入 `待发布`、`Review退回` 或 `暂不发布`。

### 发布准备服务

负责将审核通过的文章整理成可发布形态。

主要职责：

- 提供最终发布预览。
- 输出适合复制到公众号后台的图文内容。
- 记录发布准备状态。
- 为后续公众号接口发布保留适配层。

### 状态流转服务

负责统一控制文章状态变化，避免各模块直接修改状态造成规则分散。

主要职责：

- 校验状态流转是否合法。
- 拦截未审核文章进入发布。
- 记录关键状态变化时间。
- 为后续审计、历史版本和协作审核留接口。

## 核心数据对象

### Article

表示一篇公众号文章。

关键字段：

- `id`：文章 ID。
- `title`：标题。
- `summary`：摘要。
- `body`：正文。
- `category`：内容方向，取值为科技互联网、金融、文学。
- `status`：文章状态。
- `generationConfig`：生成配置。
- `createdAt`：创建时间。
- `updatedAt`：更新时间。

### ArticleImage

表示文章图片或配图方案。

关键字段：

- `id`：图片记录 ID。
- `articleId`：关联文章 ID。
- `type`：图片类型，可为已生成图片、上传图片、素材图片、配图建议。
- `url`：图片地址，未生成真实图片时可为空。
- `description`：图片描述或生成提示词。
- `source`：图片来源。
- `position`：建议插入位置。

### ReviewRecord

表示一次审核记录。

关键字段：

- `id`：审核记录 ID。
- `articleId`：关联文章 ID。
- `result`：审核结果，取值为通过、退回修改、暂不发布。
- `comment`：审核意见。
- `reviewedAt`：审核时间。

### PublishRecord

表示一次发布准备或发布尝试记录。

关键字段：

- `id`：发布记录 ID。
- `articleId`：关联文章 ID。
- `channel`：发布渠道，初版可为公众号手动发布。
- `status`：发布状态。
- `errorMessage`：失败原因。
- `publishedAt`：发布时间。

## 状态设计

主状态流：

```text
草稿中 -> 待编辑 -> 待Review -> 已通过 -> 待发布 -> 已发布
```

异常和分支状态：

```text
草稿中 -> 生成失败 -> 草稿中
待Review -> Review退回 -> 待编辑 -> 待Review
待Review -> 暂不发布
待发布 -> 发布失败 -> 待发布
```

状态控制规则：

- `草稿中` 可编辑生成配置。
- `待编辑` 可编辑标题、摘要、正文和图片。
- `待Review` 不允许直接发布。
- `已通过` 表示 review 已通过，可进入发布准备。
- `待发布` 可生成发布预览和发布内容。
- `Review退回` 必须修改后再次提交 review。
- `暂不发布` 不允许进入发布环节。
- `已发布` 作为终态，默认不再修改正文。

## 关键业务流程

### 文章生成流程

```text
用户输入主题和方向
  -> 保存生成配置
  -> 调用内容生成服务
  -> 生成标题、摘要、正文和配图建议
  -> 保存文章草稿
  -> 状态进入待编辑
```

失败处理：

- 文本生成失败时，状态进入 `生成失败`，允许用户调整参数后重试。
- 图片生成或配图建议失败时，正文可先保存，图片部分标记为缺失或待补充。

### 编辑流程

```text
用户打开图文编辑页
  -> 修改标题、摘要、正文、图片
  -> 保存编辑结果
  -> 满足最低条件后提交 review
```

最低提交条件：

- 有标题。
- 有正文。
- 有内容方向。
- 有至少一项图片内容或配图方案。

### Review 流程

```text
用户提交 review
  -> 系统校验文章完整性
  -> Review 人查看文章预览
  -> 选择通过、退回修改或暂不发布
  -> 系统记录审核结果并更新状态
```

状态结果：

- 通过：进入 `已通过`，随后进入 `待发布`。
- 退回修改：进入 `Review退回`。
- 暂不发布：进入 `暂不发布`。

### 发布准备流程

```text
文章已通过 review
  -> 生成公众号发布预览
  -> 生成可复制的发布内容
  -> 用户执行发布准备或人工发布
  -> 记录发布结果
```

初版推荐先支持人工复制发布。公众号接口发布通过发布适配层后续扩展。

## 页面概要设计

### 创作入口

展示新建文章入口、最近草稿、待 review、待发布文章。

核心操作：

- 新建文章。
- 继续编辑。
- 进入 review。
- 进入发布准备。

### 生成配置页

用于收集生成输入。

核心字段：

- 内容方向。
- 主题或关键词。
- 目标读者。
- 文章风格。
- 篇幅要求。
- 参考素材。

### 图文编辑页

用于编辑 AI 生成的文章草稿。

核心能力：

- 编辑标题、摘要和正文。
- 查看配图建议。
- 替换、上传或重新生成图片。
- 查看公众号阅读预览。
- 提交 review。

### Review 页

用于发布前人工检查。

核心能力：

- 查看完整图文预览。
- 填写审核意见。
- 标记通过、退回修改、暂不发布。
- 查看金融类风险提示。

### 发布准备页

用于发布前最后确认。

核心能力：

- 查看最终发布预览。
- 复制公众号图文内容。
- 查看图片清单。
- 标记发布结果。

### 历史文章页

用于查询和管理文章。

核心能力：

- 按内容方向筛选。
- 按状态筛选。
- 按创建时间筛选。
- 查看文章详情。

## 外部能力与扩展点

### AI 文本生成

初版通过内容生成服务封装具体模型调用，业务层不直接依赖模型接口。

可扩展能力：

- 不同内容方向使用不同提示词模板。
- 支持重新生成标题、摘要、段落或全文。
- 支持基于 review 意见定向修改。

### 图片能力

初版不绑定唯一图片来源。

可扩展能力：

- AI 图片生成。
- 人工上传。
- 素材库选择。
- 外部图片搜索。

### 公众号发布

初版推荐使用人工复制发布。

可扩展能力：

- 对接公众号草稿箱。
- 图片上传到公众号素材库。
- 自动创建公众号图文草稿。
- 发布状态回写。

### 内容合规

初版先将合规能力作为提示和人工 review 的检查项。

可扩展能力：

- 金融免责声明模板。
- 敏感词检查。
- 风险表达检测。
- 发布前强制合规确认。

## 错误处理

### 生成失败

- 记录失败原因。
- 保留用户输入的生成配置。
- 允许用户重试。

### 内容不完整

- 提交 review 前进行完整性校验。
- 明确提示缺失项。
- 不改变文章原状态。

### Review 退回

- 必须记录退回原因。
- 文章回到可编辑链路。
- 修改后必须再次提交 review。

### 发布失败

- 记录失败原因。
- 保留发布前内容。
- 允许修正后再次进入发布准备。

## 权限与安全

初版可以采用单用户模型，但业务规则必须保留 review 状态。

安全要求：

- 未通过 review 的文章不能发布。
- 暂不发布文章不能发布。
- 发布操作必须基于最新审核通过内容。
- 图片来源和生成方式需要记录，方便后续追溯。

## MVP 实施建议

第一阶段先完成以下能力：

- 文章创建。
- 生成配置。
- 图文草稿生成。
- 图文编辑。
- 提交 review。
- review 通过、退回、暂不发布。
- 发布准备和人工复制发布。
- 文章列表和状态筛选。

后续阶段再扩展：

- 多用户角色权限。
- 历史版本对比。
- 素材库。
- AI 图片生成。
- 公众号接口对接。
- 金融合规检查。

## 设计假设

- 初版使用者可以同时承担创作者、Review 人和发布执行者角色。
- 初版发布方式以人工复制到公众号后台为主。
- 图片初版至少需要有配图方案，真实图片生成或上传可以后续增强。
- 金融内容先通过风险提示和人工 review 控制，不在初版做强制自动拦截。
- 文章状态是后续开发和测试的主线。
